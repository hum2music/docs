# Harmony Engine Spec

対応：PRD §8。`packages/harmony`（`packages/music-theory`に依存）。

## 調性推定

- メロディーの音高クラス（ピッチクラス）出現頻度を音長で重み付けし、長調/短調それぞれの調性プロファイルとの適合度を評価する（提案：Krumhansl-Schmucklerに類する相関ベースの手法）
- フレーズ終端の音（特に最終音）に追加の重みを与える
- 単純な出現頻度の最大値だけで確定せず、上位N件の`KeyCandidate`を信頼度付きで保持する（PRD §8.1）。MVPは長調・短調のみ対象

## コード候補生成

- 小節・拍単位に分割したメロディー区間ごとに、候補キーの調内音から構成可能なコードタイプを列挙する
- 初期対応コードタイプ：Major / Minor / Dominant 7th / Major 7th / Minor 7th / Sus2 / Sus4（PRD §8.2）
- 各区間のメロディー音と非和声音（経過音・刺繍音等）を区別し、コード候補が区間内の主要音と矛盾しないものに絞り込む

## コード進行のスコアリング

```
S(c) = wM・M + wH・H + wV・V + wS・S
```

- **M（メロディー適合度）**：区間内メロディー音とコードトーン/テンションとの協和度。拍の強拍位置・音価の長さで重み付けする
- **H（和声進行の自然さ）**：機能和声的な遷移確率（主要三和音間の慣用的な進行、ドミナントモーションなどを高く評価するルールテーブル／遷移コスト表）
- **V（ボイスリーディングの滑らかさ）**：連続するコードの最近接ボイシング間の総移動量（半音距離の総和）の小ささ
- **S（スタイルとの適合度）**：`--style`指定に応じたコードタイプ・テンション使用頻度の重み（MVPでは中立重み。スタイルプロファイルの実体は将来的に拡充）

重み`wM, wH, wV, wS`は初期値を定数として持ち、将来的に`--style`やコンフィグで調整可能にする（提案値・要検証）。

## 進行探索アルゴリズム

- 状態：`(区間インデックス, コード候補)`
- 遷移コスト：隣接区間のコード候補ペアに対する`H`と`V`の組み合わせスコア
- 動的計画法（DP）で、曲全体のコード進行に対する累積スコアを最大化する経路を求める（PRD §8.3、単一コードの局所最適ではなく全体最適を優先）
- 上位K経路を保持し、`--chords`候補選択（P1 UI/CLI）に利用する
- 評価項目が増え、状態空間が組合せ的に増大した段階でビームサーチへの切り替えを検討する（PRD §8.3）

## ユーザー指定

- `--key`, `--chords`指定時は、該当区間の自動推定結果を上書きし、常にユーザー指定を優先する（PRD §8.4）
- ユーザー指定コードが区間のメロディーと強く矛盾する場合も、警告は出すが上書きは行う（エラーにしない）
