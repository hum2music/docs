# localhost UI Spec（完成系）

対応：PRD §14。`apps/web`。Phase 4のスコープだが、本書は完成系（Phase 4完了時点）の仕様として記述する。

## 目的

CLIの操作を置き換えるのではなく、音声入力と結果確認を直感的にするための補助UIとする（PRD §14.1）。コアロジックは一切持たず、`packages/core`を呼び出す薄いAPI層のみを`apps/web`に置く。

## 起動

```bash
hum2music serve --port 3000
```

- 完全にlocalhostで完結し、データを外部サーバーへ送信しない（PRD §14.3）
- バックエンドAPIは`packages/core`の公開関数を直接呼び出すラッパーとし、独自のビジネスロジックを持たない

## 画面構成（完成系）

画面は一画面構成から開始し（PRD §14.3）、完成系では以下のセクションを同一ページ内のステップ/タブとして持つ。

### 1. Input

- ファイルアップロード（WAV）
- ブラウザでのマイク録音（Web Audio API想定。録音データは一旦WAVへエンコードしてから既存のWAV入力パイプラインへ渡し、専用の解析経路を持たない）
- BPM指定（`--bpm`相当）
- スタイル選択（[style-profiles.md](./style-profiles.md)のプリセットから選択）

### 2. Analysis

- ピッチカーブ（生の`PitchFrame[]`を時系列グラフ表示）
- 推定された音符（`NoteCandidate[]`→量子化後`NoteEvent[]`の両方を重ねて表示し、量子化によるズレを視覚化する）
- BPM候補（信頼度付きリスト、クリックで選択・再計算をトリガー）
- コード進行候補（上位K経路を一覧表示し、小節単位でコードを選択・上書きできる）

### 3. Arrangement

- 楽器のON/OFF（`--instruments`相当）
- コード進行選択（Analysisで選んだ候補を引き継ぐ）
- Humanization設定（`--humanize`の統合スライダー＋楽器別の詳細調整。詳細は[expression.md](./expression.md)）
- 再生成ボタン（同一seedでの再現、または新しいseedでのバリエーション生成を選べる）

### 4. Export

- MIDIダウンロード（マルチトラックSMF、[export.md](./export.md)）
- JSONダウンロード（`Composition`全体、または工程別の中間JSON）
- WAVダウンロード（P1／Phase 5。MIDIレンダリング結果）

## バックエンドAPI方針

- 各画面操作は`core`パイプラインの対応するステージ関数を呼び出すエンドポイントに対応させ、エンドポイント自体に音楽理論・解析ロジックを持たせない
- 長時間処理（解析・編曲生成）は、進捗をポーリングまたはイベントストリームで返す設計とする（具体的なトランスポート方式は実装時に確定、WebSocketかSSEかはオープンクエスチョン）
- UIから渡す設定（BPM指定・スタイル・楽器選択・seed・humanize値）はCLIのオプション体系（[cli.md](./cli.md)）と1:1で対応させ、UIとCLIで異なるデフォルト値を持たせない

## 完成系で確定すべき未決事項

- マイク録音のサンプリングレート・フォーマットとサーバー側前処理の整合（PRD §6.1の入力仕様と一致させる）
- 大きめの音声ファイルに対するアップロード/処理のタイムアウト・プログレス表示方針
- 複数候補（コード進行・BPM）をUI上でどこまで並行比較できるようにするか（MVP後の拡張として据え置き）
