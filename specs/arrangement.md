# Arrangement Engine Spec

対応：PRD §9。`packages/arrangement/*`。

## 共通インターフェース

```ts
interface InstrumentArranger {
  generate(context: ArrangementContext): InstrumentTrack;
}
```

各楽器のArrangerは独立したパッケージとして実装し、`core`から差し替え可能にする（PRD §9.1、[architecture.md](./architecture.md)）。`ArrangementContext`は[data-model.md](./data-model.md)参照。

## Piano Arranger

- 生成対象（MVP）：ブロックコード、シンプルなリズミック伴奏。アルペジオ・オクターブ伴奏は拡張スコープ（PRD §9.2）
- ボイシング選択：コード進行全体を通して、隣接コード間の総移動量（ボイスリーディング距離）が最小になる転回形をDP的に選択する
- 音域制約（提案値・要検証）：演奏可能レンジを概ねC3〜C6とし、人間の手が届く範囲（1オクターブ+αの同時押さえ）を超えるボイシングを除外する
- メロディーとの干渉回避：伴奏の最高音がメロディー音より一定インターバル（提案：長2度未満の接近を避ける）以上離れるよう制約する

## Bass Arranger

- 生成対象（MVP）：ルート音中心。5度・オクターブ・経過音・次コードへのアプローチノートは拡張（PRD §9.3）
- 拍位置に応じた配置：コードのルート音を基本とし、強拍にルート、弱拍で動きを加える
- ドラムのキックとのリズム的整合：[drums.md](./drums.md)で生成されたキックのオンセット位置を参照し、ベースの打点をキックに同期または意図的にシンコペーションさせる（アーキテクチャ上、ドラム生成をベース生成より先に実行する前提とする。これはPRD本文に明記はないが、§9.3の「ベースはドラムのキックとのリズム的な関係を考慮する」を満たすための実装上の依存順として採用する提案）

## Guitar Arranger（P1/Phase 5）

- 生成対象：コードストローク、アルペジオ、ミュート、簡単なリフ（PRD §9.4）
- 考慮項目：チューニング（デフォルト：レギュラーチューニング EADGBE）、弦の本数、フレット位置、運指可能性（提案値：同時押弦の最大フレットスパン4フレット）、ストローク方向（ダウン/アップの交互を基本とする）
- 物理的に演奏不可能な押弦・運指を生成しないことを設計上の必須条件とする（PRD §9.4「ギター独自の演奏制約を無視したMIDI生成を避ける」）

## 設計上のオープンクエスチョン

- ドラム→ベースの生成順依存を、`core`のパイプライン定義でどう表現するか（単純な実行順序か、明示的な依存グラフか）は実装時に確定する
